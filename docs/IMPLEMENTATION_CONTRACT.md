# First-release implementation contract

The Rust collector, CLI, local API and Mac shell share the React interface with the hosted TypeScript service. Rust API types in `crates/core` generate `packages/core/src/generated/index.ts`; `@tokentracky/core` also supplies hosted runtime validation and arithmetic. See [accounting publication scope](ACCOUNTING_PUBLICATION_SCOPE.md) for ambiguous-history exclusions.

## Workspace

Use the pinned Rust toolchain, Node 22.18+ and npm workspaces. Vite builds the React interface; esbuild bundles the hosted Node service. Tests and benchmarks use synthetic tool folders. Set or unset tool-specific profile variables such as `CLAUDE_CONFIG_DIR` and `CODEX_HOME` explicitly when running a local experiment; changing a home-directory variable alone does not isolate profiles.

## HTTP contract

JSON errors: `{error: {code: string, message: string}}`. No sensitive internal error text. Unknown fields in publication/ingestion are rejected. Dates use UTC. Tokens are safe nonnegative integers. Cost is integer micro-USD or null for unknown.

Privacy refinement: when tool breakdown is off, the collector aggregates across tools before upload and sends `tool:'all'`. When cost sharing is off it sends `costMicrousd:null`. The server rejects fields inconsistent with the current publication. Publications always share everything (below), so these narrower uploads come only from links saved before sharing was fixed, until they are linked again. Device/bucket IDs are operational metadata; project/session identities or their hashes are never sent. Date cutoffs are UTC midnight. Up to 10 active computers publish to one account. Account reads use `cloud_account_buckets`: identical day/tool/model/token total and five-field type breakdown across computers counts once; different buckets add together. A missing cost in any copied bucket keeps its deduplicated cost unknown. A bucket's cost is stored only when its tokens could cost that much at the model's dearest list rates, plus 10% and one cent; otherwise, or when the server has no price for the model or for a token type the bucket uses, it is stored as unknown and the upload still succeeds. A cost of 0 always stands.

- GET `/api/health`: `{mode:'local'|'hosted', authConfigured:boolean, version:string, cloudUrl:string|null, supabaseUrl:string|null, supabaseAnonKey:string|null, authProviders:Array<'email'|'github'|'google'>}`. Only public configuration, never service secrets. `authProviders` lists the sign-in methods enabled in the auth project (`TOKENTRACKY_AUTH_PROVIDERS`, default `email`); it is empty when auth is not configured or in local mode.
- GET `/api/leaderboard?period=week|month|all&tool=all|claude|codex|cursor|gemini|cline|roo|kilo|opencode&q=&page=1&pageSize=20`: `LeaderboardResponse`. Anonymous, no fake/demo fallback. Profiles absent without active publication. Search preserves cohort ranks. Each profile carries `daily` (its last 14 UTC days), `last24hTokens` (every tool's tokens in the 24 whole UTC hours before the current one; absent until one of the member's computers has sent hours, as apps from before them do not) and `previousRank` (its rank in the same window and cohort at the end of yesterday UTC, or null with no earlier tokens); the response carries `trend` (community tokens for the last 30 UTC days), `toolTotals` (from builders sharing their tool split) and `totalCostMicrousd` (known shared costs, else null). Daily values respect the same history cutoff and tool cohort as the rankings. With `tool`, `tokens` and `daily` follow that tool while `toolTokens` and `costMicrousd` still cover all tools. Each returned profile carries `topBadges?: BadgeId[]`, its three highest-tier badges (ties in `BADGE_IDS` order), absent when it holds none; it is read from stored badges for the returned page only.
- GET `/api/leaderboard/around/:alias?period=week|month|all` (default `week`; any other parameter is a 400): `{items: PublicProfile[]}`, the alias and the builders ranked just above and below it in the `tool=all` rankings, so 2 rows at either end of the board. 404 when the alias is unknown, unpublished or hidden. `no-store`.
- GET `/api/profiles/:alias?period=week|month|all`: `PublicProfile`; 404 when not published.
- GET `/api/profiles/:alias/stats` (no query parameters; any is a 400): the public profile page. 404 `NOT_FOUND` when the alias is not published or invalid; the alias is matched case-insensitively. `Cache-Control: public, max-age=60`. Shape:
  ```
  {alias: string,                                   // lowercase
   periods: {week|month|all: {rank: number, tokens: number}},
   daily: Array<{day: 'YYYY-MM-DD', tokens: number}>,  // 365 UTC days ending today, oldest first, zeros included
   activity: {activeDays, currentStreak, longestStreak, averagePerActiveDay: number, bestDay: {day, tokens} | null},
   toolTokens?: Partial<Record<ToolId, number>>,     // all time; present only when shareTools
   costMicrousd?: number | null,                    // all time; present only when shareCost; null when any day is unpriced
   models?: Array<{model: string, tokens: number, costMicrousd?: number | null}>,  // present only when shareModels; largest first; cost only when shareCost too
   breakdown?: {input, output, cacheRead, cacheWrite, reasoning: number},  // all time; present only when every published bucket carries types; input + output + cacheRead + cacheWrite equals periods.all.tokens
   likes: number,                                   // likes from members who are not hidden or banned
   memberSince: 'YYYY-MM-DD',                       // UTC day the account was created
   githubLogin?: string,                            // present when the member signed in with GitHub (verified, see below)
   badges: Array<BadgeProgress>}                    // all 11, in BADGE_IDS order
  ```
  Everything respects the publication's history cutoff. `currentStreak` counts consecutive active UTC days ending today, or yesterday when today has no tokens yet; `averagePerActiveDay` is rounded.
- Achievements: computed on the server from published buckets only, on every upload and publication edit, and stored; public reads never compute them and clients never send them. `BadgeProgress` is `{id: BadgeId, tier: 0..4 /* none, bronze, silver, gold, diamond */, value: number, next: number | null /* next tier's threshold; null at diamond */}`. Thresholds are `BADGE_TIERS` in `packages/core/src/badges.ts`. Days and weeks are UTC (weeks start Monday). `podium` is the best all-time rank ever reached (lower is better, 0 never ranked); `multitool`, `polyglot` and `trendsetter` are 0 unless the tool split or model mix is shared; `trendsetter` counts models first used within 7 days of their first day on the board, among visible members. A ban deletes the account's badges and best rank.
- GET `/api/achievements/rarity` (no query parameters): `AchievementRarity`, `{builders: number /* visible published members */, holders: Partial<Record<BadgeId, [number, number, number, number]>> /* visible members holding at least bronze, silver, gold, diamond */}`. Computed at most once a minute per process. `Cache-Control: public, max-age=3600`.
- GET, PUT and DELETE `/api/profiles/:alias/like`: an account Bearer token, or a device Bearer credential (`ttd_…`, for the Mac app; it must be active and its account not banned, `403 BANNED`). GET -> `{liked: boolean}`; PUT -> 204 (idempotent); DELETE -> 204. Liking your own profile is `400 INVALID_REQUEST`; an unknown, unpublished or hidden alias is 404. PUT and DELETE are limited to 30 a minute. `no-store`. Who liked whom is never returned.
- GET `/api/community` (no query parameters): landing-page totals over every published builder, all time. Computed at most once a minute per process. `Cache-Control: public, max-age=60`. Shape: `{builders: number, newBuilders: number /* builders whose account was created in the last 7 days */, totalTokens: number, totalCostMicrousd: number | null, toolTotals: Partial<Record<ToolId, number>>, trend: Array<{day, tokens}> /* 30 UTC days ending today */, updatedAt: ISO string}`. The values equal the `period=all` leaderboard's `total`, `totalTokens`, `totalCostMicrousd`, `toolTotals` and `trend`.
- GET `/badge/:alias.svg?metric=tokens|cost|rank&period=week|month|all&style=flat|flat-square&label=…&color=…` (defaults `tokens`, `all`, `flat`, `tokentracky`, `4f56b8`): `image/svg+xml; charset=utf-8`, a two-part badge reading `<label> | <value>`. `label` is 1–30 printable characters and `color` six hex digits without `#`; both are escaped into the SVG, and anything else is a 400. Values: `1.2M tokens`, `$12.34` (whole dollars from $100) or `#3`, with ` this week`/` this month` appended for those periods. Unpublished aliases, and cost when it is not shared, show `private` (still 200, so README embeds never break). Unknown metric or period: 400 JSON error. A path not ending in `.svg` or an invalid alias: 404 JSON error. `Cache-Control: public, max-age=60`. All other cloud routes are `no-store`.
- GET `/card/:alias.svg?theme=dark|light&period=week|month|all` (defaults `dark`, `all`): a 600×180 README card with the name, rank, tokens, estimated cost when known and the top three tools as bars. The same `private` placeholder, errors and caching as the badge.
- POST `/api/visits` `{tag:'share'|'readme'}` -> 204: one arrival from a tagged link (`?ref=share` on links copied or posted from the share card, `?ref=readme` on README badge and card links). Only the UTC day, the tag and a count are stored, with no IP address, cookie, account or profile; any other tag or field is a 400. Rate-limited to 30 a minute. The web app sends it once and removes `ref` from the address bar.
- Web pages (the server returns `index.html`; the web app routes): `/` (the landing page on the hosted site, the leaderboard in the local app), `/leaderboard`, `/join` (how to get on the leaderboard), `/you`, `/u/:alias` (public profile; aliases outside the alias pattern are 404), `/privacy`, `/terms`, `/support`. Static hosting must rewrite the same paths to `index.html` and send `/api/*` and `/badge/*` to the API.
- `/api/leaderboard` also accepts `sort=tokens|cost`. Cost order puts unknown cost last; `rank` always follows tokens.
- DELETE `/api/account`: authenticated application-data erasure; provider identity lifecycle is separate. Cascades publication/devices/buckets under the account lock.
- GET `/api/account`: `{publication:Publication|null, devices:Array<{id:string,name:string,lastSeenAt:string|null}>, moderation?:{state:'hidden',days:string[]}|{state:'banned'}}`; authenticated account. `moderation` is absent unless the account is hidden for review (the UTC day keys under review, `unknown` for undated usage) or banned. It never carries reasons or thresholds.
- Moderation: a hidden or banned account is absent from every public read (`cloud_hidden_accounts`), and ranks close up behind it. A hidden account can still upload. A banned account gets `403 BANNED` from PUT `/api/publication`, POST `/api/device-auth/:code/approve`, POST `/api/device-auth/poll`, GET `/api/device-policy` and POST `/api/ingest`; a ban revokes its devices and survives account deletion.
- GitHub username: when the member joins (PUT `/api/publication`) or approves a computer (POST `/api/device-auth/:code/approve`), the hosted service reads the GitHub login from the GitHub identity in Supabase (admin API with the server-only `SUPABASE_SERVICE_ROLE_KEY`; never `user_metadata`) and stores it, or clears it when the member has no GitHub identity. A failed lookup keeps the stored value and never fails the request. Without the key nothing is stored.
- PUT `/api/publication`: `{alias}` -> `{publication:Publication}`. Any other field, including the former `consent`, `historyStart`, `shareTools`, `shareCost` and `shareModels`, is rejected as unknown (400). Sharing is fixed: every publication covers all history with tool split, model mix and cost, and `Publication` always answers `historyStart:null` with the three flags `true`. Create/edit rotates the generation and removes all previous buckets. Account creation alone publishes nothing. Migration `0010_fixed_sharing.sql` widened every earlier, narrower publication the same way, so its collector must be linked again.
- There is no DELETE `/api/publication` (404); DELETE `/api/account` is the only way off the leaderboard.
- DELETE `/api/devices/:id`: 204.
- POST `/api/ingest`: device Bearer credential; `{generation:string,collectorId:string,checkpoint:number,receipt:string,baseReceipt:string|null,buckets:PublicBucket[],hours?:PublicHour[]}` -> `{accepted:number}`. `hours` comes with an upload's first chunk only: the last day's tokens per whole UTC hour and tool, at most the host's next hour, each tool once per hour and all split or all `all`. It replaces that computer's hours; hours already more than 24 whole hours old are dropped, and every upload deletes everyone's hours that have left the window. Retry-safe revision replacements, serialized with publication saves, account deletion and device revocation. Only aggregate allowlist may leave device; no project/session IDs or their hashes. A bucket carries `model` only when the publication shares the model mix; a day is either split by model or not, never both. Model ids must match `isPublicModel` (what tools log, no spaces or free text); anything else is published as `other`.
- GET `/api/device-policy`: device Bearer credential -> `{publication:Publication}`. The collector must check the current publication before projecting/uploading; no account identity is returned. Missing/deleted/revoked membership fails closed. Ingestion still checks generation transactionally to close races.

## Local endpoints (never exposed on hosted mode)

Bind only loopback, validate Host/Origin, require per-install session authorization for reads/writes. The local server issues a secure random HttpOnly SameSite cookie through a launch URL with a one-use nonce (remove nonce from URL immediately); reject unauthenticated local APIs. Vite dev proxy must use the same session. The native shell uses the in-process router; the CLI opens the one-use launch URL. The app detects supported folders and tracks them locally by default; disabling a source stops new reads. Sharing requires an explicit hosted connection.

- GET `/api/local/detect`: `{tools:Array<{id,name,paths}>}`, the supported tools whose default log folder exists here. Checks existence only; nothing is listed or read. `/api/local/status` suggests these folders for sources without paths (otherwise the usual default).
- GET `/api/local/status`: `{sources:SourceStatus[], collecting:boolean, lastScanAt:string|null, cloudLinked:boolean, lastRefreshAt:string|null, nextRefreshAt:string|null, refreshing:boolean, pricingVersion:string}`.
- PUT `/api/local/sources/:id`: `{enabled:boolean,paths:string[]}`. Explicit user permission enables read scope. Local paths stay local.
- POST `/api/local/refresh`: run one refresh cycle (scan enabled sources, sync approved aggregates when linked, publish totals) -> status response. `409 COLLECTION_PAUSED` while paused.

Refresh cycle: one cycle runs at start once a source is enabled, every `TOKENTRACKY_REFRESH_INTERVAL_MS` (default 300,000, minimum 60,000), on wake when the last cycle is more than one refresh interval old, after a source is enabled, on resume and on demand. Cycles never overlap: a refresh requested during a cycle shares it, and a source enabled or collection resumed during a cycle queues one follow-up cycle (shared by requests made meanwhile) so the change is read at once. Pause blocks them. A failed sync retries after 2, 4, 8 and 16 minutes unless the retry would reach the next cycle.
- Range parameters: `days=7|30|90|365` (rolling, default 7), optionally with `offset=0..365` to shift that window back by that many days (`offset` equal to `days` is the previous period), or `from=YYYY-MM-DD&to=YYYY-MM-DD` (inclusive UTC days; "today" is `from=to=` today). Not both; `offset` only with `days`. The Rust local API reads saved 15-minute totals, so its rolling windows start and end on the quarter hours at or before their instants (up to 15 minutes more at the start, and less at the end of an earlier period).
- Rust local API only: `tz=Area/City`, an IANA zone the system knows (otherwise `400 INVALID_FILTER`), makes the days of `from`/`to`, `daily`, `activity` and `breakdown` local days in that zone. Rolling windows and the CSV's timestamps do not change.
- Local API: GET `/api/local/limits`, no parameters: `{tools:[{tool:'claude'|'codex', asOf:string|null, windows:[{name, usedPercent, windowMinutes, resetsAt, reset, evenPercent, projectedPercent, runsOutInMs}]}]}`. Claude Code's windows (`five_hour`, `seven_day`, `seven_day_opus`) come from its own cached reading in `.claude.json`, kept only for the account signed in there; Codex's (`primary`, `secondary`) from the latest rate-limit snapshot in its rollouts. `asOf` is when the tool took the reading. A window whose reset has passed is `reset: true` with `usedPercent: 0`. The pace fields are the use so far spread over the time gone by: `evenPercent` (the share of the window gone by), `projectedPercent` (at the reset, at most 100) and `runsOutInMs` (until 100%, only when that comes before the reset; 0 once reached); `null` when they cannot be told. Local only: never uploaded.
- GET `/api/local/summary?<range>&tool=all|...`: `UsageSummary`, including `activity` (active days, current and longest streak, best day, average per active day; streaks end today or yesterday in UTC).
- GET `/api/local/sessions?<range>&tool=...&q=...`: `{items:SessionSummary[]}`; each session lists its models (largest first) and a token breakdown (input, output, cache read, cache write, reasoning).
- GET `/api/local/breakdown?<range>&tool=...`: `{items:UsageBreakdownRow[]}`, day × tool × model tokens and cost for the cost analysis.
- GET `/api/local/projects?<range>&tool=...`: `{items:ProjectSummary[]}`; `repository` is `owner/repo` from the project folder's git remote, read from `.git/config` (or a linked worktree's shared config) only. It stays local.
- GET `/api/local/export?<range>&tool=...`: safe CSV download.
- PUT `/api/local/cloud`: `{url:string,deviceToken:string,historyStart:string|null,shareTools:boolean,shareCost:boolean,shareModels?:boolean}`. Fetch device-policy server-side, use its generation internally, and require local selected fields/history to match the hosted privacy review; edit that review first to change the scope. No user-facing generation field. Explicit linkage; the Mac app and CLI share `cloud-link.json` in the private data directory, with owner-only permissions.
- DELETE `/api/local/cloud`: stop local uploads and erase local credential, independently of hosted account deletion. What was already published stays until the account is deleted.
- POST `/api/local/sync`: submit approved aggregates and return `{syncedAt:string}`. Real network, no success simulation.
- GET `/api/local/overview`: `MenuOverview` `{today, week, month, allTime, topTool:{tool,tokens}|null, rank:number|null, alias:string|null, paused, refreshing, refreshedAt:string|null, nextRefreshAt:string|null}` for the menu bar popover and Tokens. Totals and the weekly rank come from the last refresh cycle and are dropped at UTC midnight; before the first cycle they are computed once. Alias, pause and refresh state are current.
- GET, PUT and DELETE `/api/local/likes/:alias`: read, give or withdraw a like as this device. Relayed to the linked service's `/api/profiles/:alias/like` with the device token, which goes only to the origin that issued it and never into an answer. `409 CLOUD_NOT_LINKED` when this computer isn't linked; HEAD is refused.
- Public reads relayed in local mode, like `/api/leaderboard`: GET `/api/community`, `/api/leaderboard/around/:alias` and `/api/achievements/rarity`.

## Mac app shell routes (`/api/shell/*`)

Served by the Mac app's own `app://` handler for its pages, never by the local server or the hosted service; anything else answers 404 there. Same origin, no IPC. Bodies over 4 KB are refused with 413, a wrong method with 405 and `Allow`, bad fields with `400 INVALID_BODY`.

- GET `/api/shell/state`: `{version, launchAtLogin:boolean, update:{state:'disabled'|'idle'|'checking'|'available'|'downloading'|'ready', version:string|null}}`.
- PUT `/api/shell/launch-at-login`: `{enabled:boolean}` -> state.
- POST `/api/shell/check-updates` -> state. The page can only ask for a check; downloading and installing stay native. Release builds also check after launch and every six hours, offering native Update now/Later and Restart now/Later prompts. Automatic reminders for a version are limited to once per 24 hours across relaunches.
- POST `/api/shell/open-dashboard`: `{page:'/'|'/tokens'|'/achievements'|'/settings'|'/leaderboard'}` -> 204, or `400 INVALID_PAGE`. Opens or focuses the dashboard window there.
- POST `/api/shell/menu` -> 204: shows the popover's gear menu.
- POST `/api/shell/quit` -> 204: quits the app.

## UI

The leaderboard opens first. Private pages use the local router and its authorization boundary. Public rankings come from the hosted API, with explicit empty, error and loading states. The Join page labels its sample preview as synthetic. Browser sign-in uses Supabase Auth with PKCE, offering only configured providers. Connecting publishes all eligible history with tool, model, cost and token-type breakdowns; there are no per-field sharing switches. Account deletion removes the published account. Quota readers report unsupported or unavailable data explicitly.

## Collector and synchronization

`crates/collector` reads supported local usage formats and stores allowlisted metadata in SQLite. It does not retain prompt, response or code content. Synthetic fixtures specify exact counter normalization, cumulative deltas, cache/reasoning accounting, replay, truncation and copy handling. Reader support and limitations are listed in the root README.

Sync lineage: persist a frozen pending aggregate snapshot and its random receipt before uploading. Scope local acknowledgment state to hosted origin, device credential identity (one-way hash only), and publication generation. Reuse the exact pending snapshot until every chunk returns a valid acknowledgment. Hosted ingestion binds the collector UUID, monotonic checkpoint and receipt under the account lock; stale ancestry rejects with `LOCAL_STATE_RESET`, including when restored counters have advanced. A new hosted privacy review clears totals and lineage. Operational UUIDs are not project/session identifiers.

## Hosted policy and integrity

The hosted service and operator commands require private `TOKENTRACKY_MODERATION_POLICY` configuration; see [the cloud package](../packages/cloud/README.md#moderation-policy). Policy values never enter health responses or browser configuration. Moderation can hide/review implausible totals, but usage and identity remain client reported; neither spending authenticity nor one-person-per-account is guaranteed.

Shared public sums use exact integer arithmetic. When a community sum exceeds JavaScript’s safe range, numeric fields remain safe lower bounds and `exactAggregates` decimal strings carry exact values. Per-account invalid totals are isolated rather than making public pages unavailable. PostgreSQL 15+ is required for the invoker-security views; CI uses PostgreSQL 17.
